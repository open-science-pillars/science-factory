# Practice runs

What the build environment actually ran, kept so every number in the documents can be traced to a file. Most of those files are run receipts: a run receipt is the record a run writes, with its code and inputs by checksum and every number it produced, so anyone can re-check the result without trusting whoever ran it. Below it is called a receipt. Every study log here was written by assistants (AI agents); neither the lock nor the steward's signature was recorded and no held-out data was read. Both runs were made on the tool as it stands after the third review round.

Nothing protects these logs against a rewrite: they were made before the package had a repository, and no fingerprint of them was posted anywhere before they were committed. Their fingerprints are given below so that a later copy can at least be compared with this page.

`practice-run-STUDY-0001/` is a practice run of the first real study, taken through its plan check, known-answer tests and working data. Its study log has 13 events (fingerprint `12:18a3b2993163a2099cb2439500b631737923730b217aeed1938dbb1a4d95c78e`): the study started from its request (`request.md`, the request as it stood then, bound by checksum); a change-log record with its prediction, before any test; the known-answer tests failing on the method without a quality screen (`receipts/known-answers-without-screen.json`, with the plan as it would stand without the screen kept as `analysis-plan.without-screen.yaml`); the note that failure raised; the tests and the working data passing once the screen is written into the plan; six more notes; and a second change-log record with what was observed. The seven notes are on the curation list (`curation-list.json`) and the process scorecard is `scorecard.json`. The two change-log records are the two lines of `factory/change-log.jsonl`; `sf.py check-log --study` on this directory with `--change-log` on that file reports no problem. Its known-answer results equal, number for number, those of the practice runs made before it. With the hydrology and nasa-daac-knowledge checkouts beside the package at the commits README.md names, the study tool these runs were made on reported the stage of this directory as `test`, still needing `rehearsals-pass` (both rehearsals "not run yet"), with seven open notes: the two rehearsals the plan requires need the provider's network and work that has not landed. On any other commit it also reports, with the reason, that the tests must be run again.

`system-trial-ready-STUDY-0000/` is the system trial taken as far as an assistant may take it: plan check, known-answer tests and working data all passing, rehearsal passed (4 events, fingerprint `3:470079f1ab070eb5178471f37957e6b30e80ce91ce653e89748ef976ec9ca0ae`), stage `lock`, done by people, as the study tool of that day reported it. It reads no real record: its working data is a known-answer test case with a published seed. Neither that case nor the rehearsal case holds what was put in; the rehearsal's answer is a separate file (`rehearsal/rehearsal_answer.json`), as the sealed answer will be at the opening.

`blind-test-200.json` is the blind test of the system: 200 blind test cases through the whole procedure, with the lock recorded by the harness (the script that drives the test) in throwaway directories. Of 100 cases where the idea is true, 82 were supported and 18 inconclusive. Of 100 where it is false, 94 were refuted and 6 inconclusive. No verdict was wrong. What that measures is narrow: the false cases sit at gains of 0.90 and 1.10, twice the five percent difference that matters; every case is a kind one, with no trouble put in; and the harness chose them, they were not sealed from it. The evidence right at the difference that matters, and on hard cases, is in the known-answer receipts, not here. It is, value for value, the result of the blind tests run before it.

Earlier practice runs, made before the files, keys and commands were renamed and before the third review round, were discarded: a study log is hash-chained to its names and each test event carries the tool's own checksum, so a run is made again, not renamed.

## After the layout changed

On 2026-11-26 these folders moved from `mvp/exhibits/` to `studies/exhibits/`, and the tools and the method moved with them (README.md, "Records made before the layout changed"). No file in the two practice runs was edited: the logs, the plans, the receipts and the notes are byte for byte what they were, and the fingerprints above still hold. `tools/sf.py check-log` gives the answers it gave. `tools/sf.py status` does not: the study tool and `system_trial.py` changed with the move, so the study tool of today says of both runs that their tests passed on other code and must be run again. `as-recorded/` holds the earlier bytes of those two files and, in `before-the-move/`, what the study tool said of each record on the day before; `tools/check_old_records.py` replays the old layout and compares. The plans here name their roots as they stood (`kit: ../..`); the plans of the two drafts in `studies/` were brought to the new layout, so they are no longer the same files as the plans kept here.
