# STUDY-0000: The system trial, on a blind test case

**Asked by:** the steward · **Capability:** hydrology (method under test) · **Status:** draft, not started

**The question.** In a blind test case that is generated and sealed at the moment the held-out data is opened, is the gain that was put in within five percent of one?

**Why this exists.** It is the trial of the factory itself: one study through every stage, on synthetic data only. No real record is read (the working data is a known-answer test case too), so nothing about any provider's product is produced, and no network is needed. The only thing borrowed from hydrology is its executor, as the code under test. The test case is generated by the access gate (a step of the study tool) from operating-system entropy at the opening, so neither the person nor any assistant knows whether the idea is true in it (the gain put in is 1.00 with probability one half, 0.90 or 1.10 otherwise). After the steward has decided, `system_trial.py verdict` reveals the sealed answer, says whether the factory was right, not wrong (inconclusive), or wrong, and writes that verdict into the study log.

**The seal is a seal by procedure.** The seal writes two files: the data, which is all the locked analysis is given, and the answer, in `sealed/blind_test_answer.json` inside this study. The data holds no trace of what was put in, and the two files are tied by checksum, so changing either afterwards makes the verdict refuse. But the answer file sits in the study: nothing except the rule stops a person or an assistant opening it before the verdict, the study log could not show that they had, and locked code that opened that path by name could read it. Reading the code at the lock is the barrier. docs/PLAN.md keeps `sealed/` out of every commit until the steward has decided.

**What it produces.** A qualification record for the factory, not a finding about the Earth. It is never signed as a finding; the steward's signature here records that the system trial was accepted or declined. It is accepted only when the verdict is right, which the tool enforces. An inconclusive trial exercised the procedure and did not show a right answer: it is closed as declined and another trial is run beside it. Expect that about one time in eight.

**What it exercises.** The start of the study, the analysis plan, the plan check, the known-answer tests and the working data, a required rehearsal, the lock, the access gate and its one opening, an attached write-up, independent review, the steward's signature, the verdict, a note raised on purpose and its resolution, the curation list, the process scorecard, the change log with a prediction and its outcome, and the close.

**What it does not exercise.** A request: the question is the steward's and is written in the plan, and starting from a request is exercised first by STUDY-0001. A clean place for the opening: the opening runs in the workspace where the tests ran. An analysis assistant with no route to the withheld values: that is not built.
